# 数据分析流程

## 何时使用

- 用户提供数据文件（CSV/Excel/JSON 等）要求分析、复盘或找问题；
- 需要从数据得出可行动的建议。

## 步骤

1. **对齐问题与口径**：把需求翻译成可计算的问题，明确时间范围、对比基准、分母是谁。口径有歧义时，先说清你采用的假设再往下做。
2. **先勘察数据**：读文件先看结构（表头、行数、类型）、缺失与异常，判断这份数据能不能支撑结论。数据有问题就先报告问题。
3. **用真实数据核算**：用 `Bash` 跑 Python（pandas 等）实际计算，**不要心算或编造数字**。
4. **交叉验证**：关键结论至少换一个角度验一次（换分组维度、看明细、算总量是否对得上）。对不上的地方如实指出，不要抹平。
5. **形成结论**：区分「数据说明什么」（事实）与「我建议怎么做」（判断），后者标出依据与不确定性。

## 输出格式

- 开头两三句直接给最重要的发现，不要从分析方法讲起。
- 正文：核心结论 → 支撑数据（含具体数值与口径）→ 建议行动。
- 重要数字标注来源（哪个文件、怎么算的），方便复核。
- 需要图表时生成可直接查看的图片文件并用 `sendFile` 交付。

## 注意

- 不确定的数据不要编。缺失就说缺失，并说明对结论的影响。
- 不做没有数据支撑的断言；相关性与因果要分清。
- 涉及个人隐私或敏感字段时只做聚合分析，不逐条导出明细。
