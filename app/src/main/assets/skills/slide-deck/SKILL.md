# 演示文稿设计

## 何时使用

- 需要做汇报、宣讲、培训用的幻灯片；
- 已有内容但不知道怎么组织成演示；
- 想优化现有 PPT 的结构与表达。

## 步骤

1. **先定受众与目标**：
   - 听众是谁（决策者 / 同行 / 客户 / 新人）；
   - 他们对主题的熟悉度（决定要不要解释背景）；
   - 你希望他们听完**做什么**（拍板 / 理解 / 执行）。
2. **搭叙事主线**，选一个结构：
   - **问题 → 方案 → 收益 → 行动**（提方案）；
   - **结论 → 依据 → 下一步**（向上汇报）；
   - **现状 → 挑战 → 规划**（做规划）；
   - **是什么 → 为什么 → 怎么做**（做培训）。
3. **分配页面**：每页只承载一个观点。一页讲两件事，听众一件都记不住。
4. **写结论式标题**：标题应该是结论，不是分类。
   - ❌「成本分析」 → ✅「成本下降 30%，主因是自动化改造」
   - ❌「下一步计划」 → ✅「Q3 完成三个模块上线」
5. **压缩内容**：每页要点 ≤ 5 条，每条 ≤ 1 行；能用图表就不用文字（见 `data-visualization`）。
6. **配讲稿提示**：每页写一句「这页要讲什么」，避免上台照着念。
7. **补 Q&A 准备**：预判听众最可能质疑的 2~3 个问题，准备好回答。

## 输出格式

```
# <演示主题>

## 受众与目标
## 叙事主线
（共几页、怎么串）

## 逐页内容
### 第 N 页：<结论式标题>
- 要点：（≤5 条，每条一行）
- 讲稿提示：
- 建议视觉/图表：

## 可能被问到的问题
```

## 注意

- **PPT 是讲稿的辅助，不是文档的搬运**。大段文字等于没有重点。
- 不编造数据与案例；缺的标注「待补充」。
- 不追求花哨动画与装饰，信息清晰优先。
- 需要交付时用 `writeFile` 生成 Markdown 大纲并用 `sendFile` 送达。
