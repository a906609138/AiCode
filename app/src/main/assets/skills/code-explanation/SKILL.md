# 代码讲解流程

## 何时使用

- 需要读懂一段陌生代码或一个模块；
- 想理解某个框架/库的机制；
- 学习新的语言特性或编程概念。

## 步骤

1. **先读真实代码**：用 `readFile`/`search` 读到确切实现，不凭函数名或印象推断。讲框架机制时说明依据来源。
2. **一句话总览**：这段代码解决什么问题、在整个系统里处于什么位置。
3. **分层展开**：
   - **主干**：数据从哪来 → 经过哪些处理 → 到哪去。先讲流程，别陷进细节。
   - **关键细节**：只挑真正重要的（并发控制、错误处理、性能关键路径）。
   - **易错点**：命名有误导的、看着多余其实必需的、有副作用的。
4. **讲清设计动机**：为什么用这个结构、为什么这里要加锁、为什么不那样写。**「为什么」比「是什么」更有价值。**
5. **用最小例子验证理解**：需要时给一个可运行的小例子，而不是伪代码。
6. **检验理解**：提一两个小问题，或给一个「如果改成 X 会怎样」的场景。

## 输出格式

```
## 一句话总览
## 主干流程
（步骤化，带 文件路径:行号）
## 关键细节
## 容易误解的地方
## 小检验
```

## 注意

- 不逐行翻译代码——那是最低效的讲法。
- 按对方水平调整：新手少用术语，熟手直切关键。
- 读不到的地方标「未核实」，不臆测实现。
- 不用「显然」「简单来说」这类让人不敢追问的说法。
