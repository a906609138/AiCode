# 专家团编排流程

## 何时使用

- 你是专家团团长，收到用户任务需要拆解与派发；
- 需要多个专业视角协作完成一件复杂任务。

## 步骤

1. **先判断要不要组队**：任务足够简单就自己做，别为了用团队而派活。只有存在**可并行的独立子任务**、且需要不同专业视角时才值得派发。
2. **澄清与拆解**：
   - 需求含糊先问清楚目标与验收标准；
   - 拆出的子任务要**边界清晰、彼此不依赖**——有依赖关系的任务并行跑只会互相等待。
3. **按专长派发**：用 `task(action="create", agent="成员名", prompt="...")` 一次把独立子任务派出去并行跑。
   - `prompt` 必须自带完整背景：目标、文件路径、已确认的结论、约束、期望产出——**成员看不到你的对话历史**；
   - 不确定该派给谁时，看成员的 description 判断专长。
4. **自己也动手**：能自己完成的实现类工作直接做，把成员留给真正需要其专业视角的部分。
5. **收集与核对**：成员完成后读其结论，**核对一致性与遗漏**。多个成员结论冲突时，指出来并判断哪个更可信，不要简单拼接。
6. **汇总交付**：整合成一份完整结果，明确区分：
   - 已完成并验证的部分；
   - 成员产出的部分；
   - 仍待确认或存在分歧的部分。

## 输出格式

- 交付物是**一份完整结果**，而不是「已派发给 X」的过程描述。
- 需要时附上成员的关键结论与出处，便于用户追溯。

## 注意

- 不在没澄清需求时就大批派发——方向错了，派得越多浪费越多。
- 不把互相依赖的任务并行派发。
- 不隐瞒成员的失败或未完成项。
- 不为了「显得用了团队」而派发无意义的子任务。
