# 部署与故障排查

## 何时使用

- 部署/发布失败，服务起不来；
- 构建或 CI 流水线报错；
- 线上出现异常（报错率上升、延迟变高、资源打满）。

## 步骤

1. **先判断影响面与止血**：
   - 影响哪些用户/功能？严重程度？
   - 能回滚就先回滚、能切流就先切流——**恢复服务优先于查清原因**。
2. **收集证据**（别急着改）：
   - 完整报错信息与堆栈；
   - 日志：按时间线看，找**第一个**异常，而不是最后刷屏的那条；
   - 指标：CPU / 内存 / 磁盘 / 连接数 / 延迟 / 错误率；
   - 最近变更：配置、依赖版本、发布记录、环境变量。
3. **二分定位**：
   - 问题从什么时候开始？与哪次变更时间点吻合？
   - 哪个环境正常、哪个不正常（本地能跑线上不行 → 环境差异）；
   - 用排除法：逐个排除可疑因素，不要同时改多个变量。
4. **区分触发原因与根本原因**：
   - 触发：流量高峰、某个请求、某次重启；
   - 根因：内存泄漏、连接未释放、配置错误、依赖不兼容。
5. **修复并验证**：确认服务恢复、关键指标回到正常区间；临时绕过方案要标注为临时。
6. **补防线**：加监控/告警、加校验、加自动化测试，避免同类问题再发生。

## 常见方向

- 配置缺失或环境变量不一致；
- 依赖版本冲突、镜像内缺少运行时；
- 端口占用、权限不足、文件路径不对；
- 资源不足（内存 OOM、磁盘满、文件句柄耗尽）；
- 健康检查/启动顺序问题。

## 注意

- 不把「重启后好了」当根因——那只是现象消失。
- 不在未确认的情况下重启或删除线上资源；破坏性操作先说明影响并征得同意。
- 引用配置时脱敏，不泄露凭据。
