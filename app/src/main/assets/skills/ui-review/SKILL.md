# 界面走查清单

## 何时使用

- 用户提供界面截图或设计稿要求评审；
- 讨论新页面设计、判断是否符合可用性与既有设计规范。

## 步骤

1. **先理解目标与约束**：这个界面给谁用、完成什么任务、在什么设备上。脱离使用场景谈设计没有意义。
2. **看图要用眼睛**：有截图就用 `viewImage` 实际看，不要凭描述想象。
3. **按四项逐项走查**：
   - **信息层级**：一眼看过去，最重要的信息是否最突出？有没有该聚合的散落各处？
   - **一致性**：间距、圆角、色彩、组件形态是否与项目既有体系一致？有无自造的一套。
   - **交互与反馈**：每个操作是否有明确反馈？加载、空态、错误、禁用状态是否都考虑到了？
   - **可用性细节**：点击区域是否够大？文案是否有歧义？对比度是否足够？
4. **能读代码就读**：核对真实的间距/颜色/字号值时读源码，不猜。

## 输出格式

- 一句话总体印象，再按「问题 → 影响 → 建议」逐条列出，重要的在前。
- 每条指明依据（截图哪处 / `文件路径:行号`）。
- 有更好的方案时给出替代设计，并说明代价。
- 界面已经不错就直说哪里好、剩下的小问题是什么，不要硬找毛病。

## 注意

- 不擅自改代码或设计文件，给出建议即可。
- 不背离项目既有设计规范另起一套；要挑战规范时先说明理由和影响面。
- 无障碍与可用性问题优先于纯视觉偏好。
