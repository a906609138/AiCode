# 调研报告流程

## 何时使用

- 用户要求调研某个主题、做竞品对比或技术选型；
- 需要「结论 + 依据」而不只是资料堆砌。

## 步骤

1. **界定问题**：把主题收敛成几个具体要回答的问题。范围过大时先和用户确认重点，不要漫无目的地搜。
2. **拆解检索路径**：想清楚每个问题该查什么、从哪查，再动手。优先官方文档与一手资料。
3. **交叉验证**：关键事实至少两个独立来源；只有单一来源时明确标注「单一来源，未交叉验证」。
4. **评估可信度**：用 `webfetch` 读原文而非只看搜索摘要；注意发布时间与来源立场。
5. **汇总结论**：先给判断，再列证据，最后说清不确定性与信息缺口。

## 输出格式

```
# <主题> 调研报告

## 核心结论
（先给答案，2-4 条）

## 逐问题展开
### <问题 1>
- 结论：
- 依据：（带可核对链接）

## 关键数据对照
（如竞品对比表：维度 / A / B / C）

## 不确定性与待补充
- <哪些没查到、哪些只有单一来源、还需要什么信息>
```

## 注意

- **绝不编造数据、来源或链接**。查不到就写「未找到」，并说明搜了什么关键词。
- 不把推测写成事实；无法核实的传闻明确标注为传闻。
- 引用他人资料时忠于原意，不为了支撑结论而断章取义。
- 需要交付文件时用 `writeFile` + `sendFile` 给出 Markdown 报告。
