# 算法解题流程

## 何时使用

- 遇到一道算法题需要解法或讲解；
- 面试准备、刷题训练；
- 有思路但不确定正确性或复杂度。

## 步骤

1. **读清题意与约束**（先别写代码）：
   - 输入输出的确切含义、边界情况；
   - 数据规模：`n` 多大？决定允许的时间复杂度；
   - 是否有序、有无重复、取值范围、是否可能为空。
2. **先给暴力解法**：最直白的做法 + 它的复杂度。有了基准，才知道要优化什么。
3. **找优化点**：问「哪一步在重复劳动」。常见方向：
   - 用哈希表把「查找」从 O(n) 降到 O(1)；
   - 有序 → 双指针 / 二分；
   - 重叠子问题 → 动态规划（先想状态定义与转移方程）；
   - 需要频繁取最值 → 堆；
   - 区间/子数组 → 前缀和、滑动窗口。
4. **验证思路**：用手推几个小例子，特别试**边界**（空、单个元素、全部相同、极值）与**反例**。
5. **实现**：写清楚变量含义；易错处（下标越界、初始值、循环边界）单独检查。
6. **实测**：用 `Bash` 实际运行，至少覆盖正常用例 + 边界 + 反例。**没跑过不许说验证过**。
7. **给复杂度**：时间与空间都要给，并说明怎么算出来的。

## 输出格式

```
## 思路
（从暴力到优化的推演，讲清为什么）
## 复杂度
时间 O(...) / 空间 O(...)
## 代码
（关键步骤带注释）
## 验证
（跑了哪些用例、结果如何）
```

## 注意

- 教学场景先给提示、留思考空间，别一上来贴答案。
- 不炫技：可读性优先，不写没必要的位运算技巧。
- 不用「应该能过」代替实际运行。
