# 专家

专家是**可召唤的会话角色**。召唤之后，当前对话会以它的人设、方法论与工具链来完成任务——相当于请来一位对口领域的顾问，不必每次从头交代「你该怎么干」。

## 专家、技能、子代理怎么选

| | 是什么 | 什么时候用 |
| --- | --- | --- |
| 技能 | 能力扩展包：让 AI 会做某件事 | 需要 AI 具备某种具体能力 |
| **专家** | 会话角色：懂某个领域，按既定方法干活 | 有一个明确问题，想让它以专业视角处理 |
| 子代理 | 独立会话：另开一条线并行做事 | 任务能拆成互不依赖的几块 |

一句话：**技能是能力，专家是能力加经验，子代理是分身**。

## 召唤专家

输入框上方、模型按钮右侧有**专家按钮**（人形图标）：

1. 点开看到可用专家列表；
2. 选中一位，当前会话立即以它的身份运行；
3. 想退回默认身份，选「**不使用专家**」。

召唤后：人设与工作方法生效，工具集按定义收窄；已召唤时按钮图标变为高亮色，便于随时看出当前身份。

专家只作用于当前会话，**不会**影响其它会话，也**不会**改变你选择的模型——除非专家定义里自己绑定了模型。

## 专家从哪里来

每个专家是一个 Markdown 文件，放在下列目录其一：

| 位置 | 作用域 | 说明 |
| --- | --- | --- |
| `~/.aicode/experts/` | 全局 | 跨工作区共享，本地模式对应 App 私有目录下的 `aicode/experts` |
| `<工作区>/.aicode/experts/` | 项目级 | 只在当前工作区生效，可随项目提交到 git |

同名时**项目级优先**。

App 自带若干内置专家，首次启动释放到全局目录；**改过、重写或删掉的内置专家不会被升级拉回**。

## 定义格式

文件开头是 YAML frontmatter，其后正文就是专家的人设与方法论：

```markdown
---
name: code-reviewer
displayName: 代码评审官
description: 对改动做系统性评审，输出可执行的修改建议
category: dev
tools: [readFile, list, search, Bash, sendFile]
inject: [mainRules, projectRules, memory]
---

你是资深代码评审官……（正文即人设与工作方法）
```

| 字段 | 必填 | 说明 |
| --- | --- | --- |
| `name` | 是 | 唯一标识，建议与文件名一致 |
| `displayName` | 否 | 列表里显示的名字，缺省用 `name` |
| `description` | 否 | 一句说明，帮助你在列表里辨认 |
| `category` | 否 | 分组标签，仅用于归类展示 |
| `tools` | 否 | 工具白名单；不写表示可用全部工具 |
| `disallowedTools` | 否 | 工具黑名单，优先级高于白名单 |
| `inject` | 否 | 注入哪些基础规则片段，取值 `mainRules` / `projectRules` / `memory` / `skills` / `base` |
| `provider` / `model` | 否 | 绑定模型；不写则沿用当前会话的选择 |
| `reasoningEffort` | 否 | 思考强度 `low` / `medium` / `high` |
| `type` | 否 | 写 `team` 即为**专家团**，配合 `members` 使用 |

正文为空视为无效定义，会被跳过。

## 专家团

把 `type` 设为 `team` 并列出成员，就是一个专家团：

```yaml
---
name: dev-team
displayName: 研发小队
description: 一条需求从评审到落地
type: team
members: [code-reviewer, tech-writer]
---
你是团长，先拆解任务，再把子任务派给成员并行推进，最后汇总成完整交付。
```

召唤专家团后，你是和团长对话：它负责拆解、派发、汇总；成员在各自的会话里并行工作，可在侧边栏查看进度。

## 常见问题

**召唤了但看不出变化？**
专家的作用体现在回答风格与可用工具上，界面不会额外显示面板。可让它做一件只有该专家才擅长的事来确认。

**专家列表是空的？**
目录里没有 `.md` 文件，或文件正文为空。放一个文件后重新进入该页面即可看到。

**专家定义写错了会怎样？**
单条解析失败只跳过该文件，不影响其它专家与对话；其余专家照常可用。
